# Ovis v2 — Rust 网关交付任务（第 4 稿）

设计与契约：`docs/v2-rust-gateway.md`。下表是待实现的交付计划；写入范围是未来任务权限，不表示本次修改这些文件。所有任务均待执行，命令是各任务必须产出的 validator，不声称它们已存在或已通过。

硬约束：归属单元是 **socket + 有状态 HTTP + 全部 pane claims + 共享 pane 的其他 clients 的递归闭包**；本版迁移整个 local core，不做部分 socket/pane 分流。T-07/T-08/T-11 使用同一组 fixtures：一 socket 两 pane、两 clients 一 pane、role/吊销、规范路径及 `/api/machines/local/*` alias 的 create 首消息 HTTP、prompt answer/Stop、重连 replay。alias 必须先规范化再选 owner，同时保留原机器开关/Origin/请求头/允许路径限制；E 独立收录 server alias 来源，不能只扫 SPA。T-08 正向交接与 T-11 回退各自执行 §4 全结果/故障矩阵，T-07 test seam 不替代真实切换。公开端口在 T-11 前仍是 v1；T-08 等待 T-10 访问层和 T-09 conversation；远端整连接/对应 HTTP 仍代理，目标不可变。

每条备注命令必须先补 harness，记录 **HEAD 语义红 / 指定错误实现红 / 候选绿**；module-not-found 不作语义红。仅用 runner 的隔离进程/端口/状态，不操作用户服务。provenance 绑定 spawn 的 SHA/PID/listener：native 在 v1 缺席仍成功，proxy 有实际 upstream hop 且 v1 缺席失败，RPC 绑定 fixture daemon。ordinary 构建测真实 ingress/交接，instrumented 构建另测真实判定事件/mutants，分记 v1/Rust SHA、flags、assertion 清单；到达 admission 则 owner/count=预期 owner/1，通道提前拒绝则无 admission owner/count=0，绝不用响应头计数。完整 oracle 见设计 §2/§4/§10；`cargo +1.96.1` 构建。
